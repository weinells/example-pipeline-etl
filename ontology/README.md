## Modeling Decisions

- `CustomerDevice` and `CompanyHardware` are disjoint subclasses of `Hardware`.
- A modem belongs to exactly one customer; a customer may have multiple modems.
- A router belongs to exactly one customer; a customer may have multiple routers.
- `isAncestorOf` is transitive and is directed from router to modem and modem to CMTS.
- Feature fields are modeled as direct decimal datatype properties of `FeatureVector`; the source data does not provide observation identifiers for separate measurement instances.
- `ServiceQualityLabel` is distinct from `Prediction`. Labels are generated by a rule, while predictions are generated by a persisted model.
- The current data has CMTS-side measurements but no CMTS identifier; the CMTS is therefore modeled conceptually rather than as a current data instance.
- Measurement units remain unspecified because the source documentation does not provide them.

## Competency Questions

Use these questions to validate future ontology revisions. They become executable queries when ontology instances are supplied.

- Which telemetry properties make up a FeatureVector for a customer, modem, and router mapping?
- Which ServiceQualityRule generated a ServiceQualityLabel, and which FeatureVector did it use?
- Which PersistedModel generated a Prediction, and which FeatureVector is that prediction for?
- Which routers are ancestors of a modem, and which modems are ancestors of a CMTS?
- Does each modem and each router belong to one customer?

## Validation

Parse `examplepipeline_ontology.owl` with an RDF/OWL parser before merging ontology changes. Run an OWL reasoner when ontology changes require class or property consistency verification.

Recommended reasoners:

- Use Protégé with HermiT for an interactive consistency and classification review.
- Use ELK when fast OWL EL reasoning is sufficient.
- Use Pellet when broader OWL expressiveness is required.
